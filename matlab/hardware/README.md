# MATLAB 实物控制

`start_pendulum.m` 是项目根目录入口；核心为 `matlab/run_hardware.m`。运行链路为 MATLAB → 厂商 .NET 程序集 → NI PCI-6602 / Advantech PCI-1723。全部控制、传感器换算、状态机、日志和停机处理均为 MATLAB 源码。

## 运行前提

本机已识别 `Dev1 / PCI-6602` 和 `PCI-1723,BID#15`。`.NET` 组件属于板卡驱动安装内容，MATLAB 使用内置 `NET.addAssembly` 加载。驱动路径、接线及参数集中在 `ph_config.m`；迁移值来自 2026-09-08 项目配置。不会读取外部工程或 C++ 配置文件。更换驱动安装路径时修改该配置。

当前极性为正电压向右、小车编码器向右递减；回中时验证编码器极性，不自动尝试相反的限位释放方向。二杆编码器测相对关节角，转换为第二杆绝对角后控制。第一杆下垂到直立加半圈参考；第二关节使用下垂时相对参考。

自动零点只判断编码器是否静止，无法仅凭增量编码器区分下垂与被人扶住的其他角度；启动前两杆必须自由下垂。已标定的静止电压保留在配置中；本次未重新做电机零速标定。

## MATLAB 命令

在项目根目录：

```matlab
addpath('matlab','matlab/hardware');
ph_probe;                 % 仅枚举，不打开输出
ph_check_inputs(1);       % 一阶真实编码器、限位读取
ph_check_inputs(2);       % 二阶真实编码器、限位读取
ph_check_timing(2,5);      % 只读输入 + 控制计算时序，不使能电机
verify_hardware_port;     % 控制器回归，不使用驱动
verify_homing;            % 模拟回中、零点、超时测试
verify_cleanup;           % 异常退出清理、保存日志测试
verify_output_api;        % 只向厂商 DemoDevice 和 NI SimDev1 写输出
```

`verify_output_api` 会断言 NI 目标是模拟设备，研华目标固定为 DemoDevice；真实板卡只读取编码器。这个测试用于确认 MATLAB 的 .NET 输出重载、使能和停止调用有效，不能代替实物输出验证。

实物运行（会移动设备）：

```matlab
start_pendulum(1);
start_pendulum(2);
% 可设置控制阶段时长；回中和零点等待另有超时：
r = run_hardware(2,struct('duration',60));
```

每次运行测量两侧限位，低速复测并校验往返行程，在本次计数坐标下回中；随后断开伺服等待下垂稳定，捕获零点，再进入控制。日志独立保存至 `matlab/output/hardware/<运行目录>/run.mat`，包括配置、本次中心、参考计数、状态、控制电压、阶段、运算耗时和故障报告。

## 控制及停机

一阶保留原硬件 ETlab 控制律和积分器更新顺序：100 Hz 采样，ACC2VOL 内部 0.005 秒积分系数、能量起摆、LQR 和 ±1 V 限幅。其首次下垂采样及随后静止采样行为与原 C++ 相同；它依赖摆杆自然运动/测量变化继续能量注入，尚未实测 MATLAB 版本是否可靠完成起摆。

二阶保留 200 Hz 三阶段控制：第一杆能量起摆、第一杆保持加第二杆起摆、双杆 LQR；包含捕获辅助、跌落回退、速度滤波、加速度到速度参考的积分以及抗饱和 PI。

每次采样检查计数跳变、物理限位、软件行程、数值有效性和时间预算；软限位抑制向外命令，二阶保留向内恢复电压。一阶另设 0.30 m 硬停止以避免原起摆对数项超出定义域。回中允许以既定方向低压离开被触发的限位，控制阶段任何物理限位触发即停机。

正常结束、异常或 Ctrl+C 通过 `onCleanup` 调用独立句柄记录对象，依次尝试 AO=0 V 和伺服关闭，再释放任务并保存日志。进程被强制杀死、MATLAB 卡死或驱动阻塞时，MATLAB 清理回调不能保证执行；独立物理急停必须保留。原 C++ 的独立监控线程没有在 MATLAB 中等价实现，MATLAB 定时器也不能提供独立于解释器阻塞的保护。

## 已做验证与未完成项

- MATLAB R2021a 成功枚举真实 NI/研华设备。
- 一阶读取 200 次、二阶读取 400 次，编码器及两个限位读取通过，无真实输出。
- 控制器回归通过：单步数值、编码器符号、二杆相对角、阶段切换/跌落回退、跨角度边界、限幅、非有限输入及位置域检查。每阶另外运行 10000 次控制更新。
- 模拟回中、静止零点、搜索超时、异常清理及日志保存通过；模拟输出 API 通过。
- 原有理想模型的一阶和二阶起摆仿真均通过。它们是加速度输入模型，并不包含真实电压闭环，不能证明实物起摆成功。
- 5 秒只读时序试验：一阶 500 周期，最大输入+计算约 0.775 ms；二阶 1000 周期，最大约 5.8 ms，超过 5 ms 周期。该试验不包含真实 AO/伺服写入。Windows/MATLAB 不提供硬实时保证；运行器在运算超期时停机，不能声称 200 Hz 全程满足。
- 尚未使能真实伺服、实测 AO 电压、验证实际回中或完成实物一/二阶起摆；需操作者在场授权后分步验收。不得把仿真或模拟输出测试视为实物验收。

运行时序可能因 JIT、垃圾回收和系统负载变化，应先执行只读测试；代码保留原采样频率，没有为避免报错而放宽控制期限。

驱动用法参考：[NI 官方 .NET 任务与读写说明](https://www.ni.com/en/support/documentation/supplemental/21/using-ni-daqmx-in-text-based-programming-environments.html)、[研华官方 MATLAB 驱动示例说明](https://www.advantech.com/en/support/details/faq?id=1-JL6L9)。实际接口签名已对照本机程序集及 `C:\Advantech\DAQNavi\Examples\Matlab` 校验。

## 启动时序检查修复

启动现在先执行 100 次只读输入/控制预热，再测量连续 200 个周期；验收仍要求每个周期耗时及启动迟到量小于原采样周期。失败时将预热、最大/中位耗时和超期次数写入运行日志的 preflight 字段，输出保持未打开。R2021a 本机复测：二阶冷启动最大 19.890 ms，预热后最大 0.870 ms，200 周期无超期。该结果仅是当次只读检查，不保证后续 Windows 调度始终满足期限。

程序集优先按 GAC 名称加载，安装路径作为回退；同时修正数字输出任务 Timeout 的毫秒单位。
